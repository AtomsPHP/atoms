## `atoms.json`

The `atoms.json` file is generated by `vendor/bin/atoms init`. It describes where your Atom code lives, as well as environment-specific settings.

```jsonc
{
    "project": "my-app",
    "paths": {
        "atoms": "app/Atoms",
        // DTOs or other shared code used on the Atom side and the App side:
        "shared": "app/Atoms/Shared"
    },
    "environments": {
        "production": {
            "worker_name": "my-app",
            // Optional when the credentials reach one account; required when
            // they reach more than one.
            "account_id": "",
            "debug_endpoints": false,
            // Where the Worker reaches your app for app() and dispatch().
            "callback_url": "https://example.com/atoms/callback"
        },
        "staging": {
            "worker_name": "my-app-staging",
            "account_id": "",
            "debug_endpoints": true,
            "callback_url": "https://staging.example.com/atoms/callback"
        }
    }
}
```

| Key | Required | Default or fallback |
|---|---|---|
| `project`<br>Project slug, recorded in the build manifest | yes | — |
| `paths.atoms`<br>Directory holding your Atom classes | yes | — |
| `paths.shared`<br>Directory of code used on both the Atom side and the App side | no | `<paths.atoms>/Shared` |
| `environments.<name>.worker_name`<br>Name of the Cloudflare Worker this environment deploys to | yes | — |
| `environments.<name>.account_id`<br>Cloudflare account that owns the Worker | no | — |
| `environments.<name>.callback_url`<br>URL where the Worker reaches your app for `app()` and `dispatch()` | no | — |
| `environments.<name>.debug_endpoints`<br>Whether the Worker exposes its debug endpoints | no | `false` |
| `environments.<name>.custom_domains`<br>Hostnames the Worker answers on | no | `[]` |

Structural problems in this file are reported as
[ATOMS-E070](/reference/errors/#atoms-e070). Every key under
`environments.<name>`, and the order the overridable ones resolve in, is
described in [Environments](/guides/environments/).

Each environment may also have one **uncommitted** file,
`.env.atoms.<environment>`, for values that belong to one machine or one secret
store rather than to the repository. Which environment a command acts on, where
each of its values comes from, and what that file holds are the subject of
[Environments](/guides/environments/) as well.

How your application calls a deployed Worker is configured in the application
itself, not in `atoms.json`. Set `ATOMS_ENDPOINT` in the monolith to the
Worker's URL. See [Laravel](/getting-started/laravel/) or
[Symfony](/getting-started/symfony/).

## `atoms-worker/wrangler.jsonc`

The Worker scaffold command that `atoms init` prints writes this file. It is
Cloudflare's view of the Worker: logging, placement, limits and runtime vars.

Put logging, placement, limits and other runtime settings at the **top level**
of this file. `atoms deploy` and `atoms dev` derive a copy of it for the
selected environment and hand that copy to Wrangler, so what you write here
reaches every environment alike, and Wrangler's `env.<name>` sections do not
apply. Anything that differs per environment, `debug_endpoints`,
`callback_url` and `custom_domains`, lives in `atoms.json` and is
applied to the copy. [These are not Wrangler
environments](/guides/environments/#these-are-not-wrangler-environments)
describes the copy. The Durable Object binding and migrations are owned by
`atoms-runtime-cloudflare upgrade`.

Routes or custom domains written at the top level of this file are left out
of the copy, and `atoms deploy` prints a notice naming them. Declare each
hostname under `custom_domains` on the environment that serves it, as [Where
each environment is
served](/guides/environments/#where-each-environment-is-served) describes.

## `atoms-composer.json`

`atoms init` writes this file too. It lists the Composer packages that ship
inside the Atom, separate from your application's own `composer.json`:

```json
{
    "require": {
        "atoms/database-illuminate": "^0.6"
    }
}
```

Only `require` and `repositories` are accepted, and required packages must be on
the Atoms allowlist; anything else is
[ATOMS-E071](/reference/errors/#atoms-e071). `atoms build` resolves the file and
writes `atoms-composer.lock` beside it — **commit that lock file**, since it is
what makes a build reproducible.

See [Deploy](/guides/deploy/) for how the vendor stage resolves, caches and
ships those packages.
